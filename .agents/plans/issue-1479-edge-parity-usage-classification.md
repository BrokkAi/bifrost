## Purpose / Big Picture

Bifrost answers "what does this token resolve to?" and "who uses this declaration?" with two completely independent derivations. The forward answer comes from the occurrence rows built by `crates/bifrost-analysis/src/analyzer/structural/occurrence_rows.rs`: every classified identifier token carries an `OccurrenceTarget` (resolved units, a lexical binding, or a typed unresolved status), produced by the `get_definition` resolver family. The inverse answer comes from `find_usages` in `crates/bifrost-analysis/src/analyzer/usages/`: given a declaration, each per-language usage index enumerates `UsageHit` sites, and the RQL `references-of` step projects them into `CodeQueryReferenceSite` rows. Nothing checks that these two surfaces agree. When they disagree — a call site resolves forward to a method but never appears in that method's usage listing, or a usage listing names a site whose forward resolution picks a different declaration — the result is a wrong dead-code verdict, a wrong rename, or a missing caller, and today the only way to notice is a human comparing tool outputs.

The 11 mined regressions in the issue inventory are exactly this shape. `02abec289` is titled "Fix Java forward-inverse reference parity" and `7cac14b63` "Fix Python forward-inverse reference parity": in both, sites that `get_definition` resolved to a target were missing from that target's inverse usage surface (or present with the wrong classification). `5b4b0371f` ("Reuse Rust receiver type proof for usages") is the proof half: the forward resolver had receiver-type proof the usage side re-derived worse, so the same edge was `Proven` in one direction and `Unproven` (or absent) in the other. `5f553eaf3` ("scan_usages: uniform, honest, inspectable same-owner usage policy") is the classification half: whether a same-owner reference counts as a usage was decided inconsistently per language. `6b8ad034e` (C++ bare implicit-this calls recorded as unproven inbound rather than dropped) is the uncertainty-preservation half: an unprovable edge must degrade to `Unproven`, never disappear. The remaining six (`2436a66274`, `76faeff2d`, `7a562e143`, `a04e3e85d`, `ec9ed1787`, `f852b12d5`) are per-language holes where one direction knew an edge the other did not.

After this change, four things work that do not work today:

1. RQL can enumerate *reference edges* as one canonical typed row family. An edge row states the site (file, range, and the same content-scoped `ast_id` a structural capture or occurrence row uses, when the site token is a facts-arena node), the target declaration, the reference kind (call, field read/write, type reference, ...), the proof (`proven` / `unproven`), the usage-kind and surface classification (plain reference, import, re-export, self-receiver, definition site, override declaration; external-usages vs editor-visible), the owner relation of site to target (same owner, inherited owner, self, external), which producer derived it (`forward` from the resolver, `inverse` from the usage index), and the workspace generation it was derived in.
2. Both projections answer the same semantic contract. `edges-of` (inverse: seed declarations, enumerate their incoming edges) and `edges-from` (forward: seed files or occurrence sets, resolve each reference site to its target edge) return the same row shape with provenance retained, so a query can hold both sets at once.
3. RQL can compare edge sets relationally. A field projection selects the comparison key — any subset of site, target, kind, proof, surface — and equijoin, anti-join, and symmetric difference over that key are real operators, so "forward edges with no inverse counterpart" is one query whose result rows carry both provenance chains (the resolver outcome that produced the forward edge; the usage strategy that produced or should have produced the inverse edge).
4. The RQLP `assertion` analysis kind gains edge-parity asserts: a policy can require that the complete proven forward edge set and the complete proven inverse edge set agree field-for-field within one immutable workspace generation, and that classifications match explicitly (never inferred from counts). Findings name the unmatched edge and both provenance chains. Any incompleteness — an unsupported language axis, a truncated usage listing (`TooManyCallsites`, the reference-candidate cap), resolver diagnostics, or a generation mismatch — yields `unreliable` / `Inconclusive`, never a clean pass.

Observability: after the final milestone, `cargo nextest run` shows edge queries returning classified rows with both provenances in the four deep languages (Java, Rust, Python, JS/TS); the policy CLI runs an edge-parity assertion that fails on a seeded one-sided-edge fixture and passes on its near miss; and the conformance suite re-expresses the mined regression shapes as fixtures that would have caught them.

Findings from the pre-plan survey (2026-08-05). Update this section as implementation proceeds.

- Observation: `UsageHit` equality and hashing deliberately exclude the fields this issue wants compared. `crates/bifrost-analysis/src/analyzer/usages/model.rs:11-13` documents that equality keys only `(file, start_offset, end_offset, enclosing)` so duplicate hits from different patterns collapse; `kind`, `proof`, `confidence` and `reference_kind` are excluded. Two hits that disagree on proof or kind therefore dedup to whichever arrived first inside the `BTreeSet<UsageHit>`. A field-for-field parity comparison cannot be built on this identity; the canonical edge row needs its own key that includes the compared fields, and the collapse itself is a place where classification disagreements hide today.
- Observation: the inverse projection into RQL already exists and is the natural inverse producer. `references-of` / `used-by` run `find_usages` per seed declaration and mint `ReferenceHit` rows via `reference_hit_for_target` (`crates/bifrost-analysis/src/analyzer/structural/search/expansions.rs`), mapping `FuzzyResult::Success` hits to `Proven`/`Unproven` and `FuzzyResult::Ambiguous` hits to `Unproven`, then render `CodeQueryReferenceSite { path, language, range, target, enclosing_declaration, usage_kind, proof, reference_kind }` (`search/results.rs:1116`). The truncation honesty also exists there: `ReferenceCandidatesOmitted` diagnostics with `Incomplete` impact and an `exhausted` flag.
- Observation: the forward surface stops at `OccurrenceTarget` and does not state edges. `occurrence_rows.rs` collapses each resolver outcome to `Resolved(units)` / `Lexical` / `Unresolved(status)` (`:447-451`); the #1474 candidate trace adds tiers and boundary status. A forward *edge* (site plus one target with kind/proof/classification) is a projection of these plus the reference-kind classification that today only the inverse side computes (`classify_reference_kind`, called from `expansions.rs` when the hit lacks one).
- Observation: `usage_graph`'s inverted edge build drops rows by design that occurrence rows keep. `EdgeCollector::record_kind` (`crates/bifrost-analysis/src/analyzer/usages/inverted_edges.rs`) drops self-references and references inside the callee's own definition, requires both endpoints to be graph nodes, and dedups edge weight by `(file, line, caller)`. Raw set equality between surfaces is therefore wrong by construction; the rule contract's "appropriate surface classification" means the parity comparison must be per-surface, with the drop rules expressed as classification (self, declaration-site) rather than absence.
- Observation: the classification vocabulary is spread over three partial enums. `UsageHitKind` (reference/import/reexport/self_receiver/definition/override_declaration, `model.rs:26`), `UsageHitSurface` (external_usages vs lsp_references, `:47`, with `included_in` as the only classifier), and `ReferenceKind` (eight source-level kinds, `:212`). "Same-owner" and "inherited-owner" appear only as per-language policy inside usage strategies (the subject of mined commit `5f553eaf3`), not as data.
- Observation: set composition exists but cannot express parity. `SetOperator` is `Union | Intersect | Except` (`query/ir.rs:800`), operating on whole typed endpoints; there is no field projection, no equijoin on a chosen key, no anti-join with retained provenance from both sides, and no symmetric difference. `except` composed twice cannot substitute because each direction loses the other side's provenance and the comparison key is the full row identity, which includes exactly the fields (proof, kind) whose disagreement we want to surface rather than treat as distinctness.
- Observation: the assertion kind is ready for a new family. `crates/bifrost-policy/src/schema.rs:221-224` registers `assert`, `assert-resolution`, `assert-reaching`, `assert-boundary` as keyword-pair records under `OwnerApplicability::POLICY_ASSERTION`; the #1474 evaluator already implements the soundness rule (incomplete inputs yield `Inconclusive` with zero findings) that edge-parity asserts must inherit.
- Observation: `callers` already has a completeness vocabulary to reuse. `CallTraversalCompleteness` (`query/schema.rs:1310`) distinguishes `exhaustive` from `proven_subset`, and the schema note at `:225` records that the call-traversal surface "supports positive findings but never the assertion that all callers were" found — which is precisely the gap the edge domain's per-axis completeness must close before a parity assert can be sound.
- Observation: the four deep adapters (Java, Rust, Python, JS/TS) are the only languages with a forward surface; every language has an inverse surface. Parity is therefore only assertable where both projections exist, which fixes the claimed-language set without any new decision.

## Decision Log

- Decision: the claimed languages are Java, Rust, Python, and JS/TS — the adapters with deep occurrence support from #1473/#1474. The mined inventory's C# (`2436a66274`, `76faeff2d`), C++ (`6b8ad034e`), Go (`f852b12d5`) and Scala (`7a562e143` in part) shapes are represented by same-shape fixtures in claimed languages where the shape exists there (self-field references, nested-type usage, implicit-this calls, cross-package qualified field types), and recorded as boundary/abstention tests otherwise.
  Rationale: parity needs both surfaces; only the deep adapters have a forward one. Same partial-rollout logic as #1474's Scala decision.
  Date/Author: 2026-08-05, Fable 5.
- Decision: the canonical edge row is a *projection contract over the two existing producers*, not a third stored graph. The forward producer projects occurrence rows plus the resolution trace; the inverse producer projects `find_usages` results exactly as `references-of` already consumes them. No new persistence, no new resolver, no re-implementation of usage strategies.
  Rationale: the epic's charter says reuse typed domains and production analyses rather than build a second solver; a stored third graph would be a second opinion that can itself diverge.
  Date/Author: 2026-08-05, Fable 5.
- Decision: the edge comparison key is a declared field projection (site identity, target identity, reference kind, proof, surface), and the parity operators (equijoin, anti-join, symmetric difference) take the projection as an explicit argument rather than comparing full row identity. Site identity is the occurrence `ast_id` where the site token is a facts-arena node, else the `(path, byte-range)` pair over the same content identity; target identity is the declaration's `CodeUnit` identity as rendered today (fq-name plus source), with the stronger canonical identity deferred to #1475.
  Rationale: full-row identity treats a proof disagreement as two unrelated rows; the projection makes the disagreement the finding. Byte-range identity over one content identity is exact, not heuristic (the #1474 M2 observation).
  Date/Author: 2026-08-05, Fable 5.
- Decision: owner-relation classification (`same_owner`, `inherited_owner`, `self`, `external`, plus `declaration_site` as a site class) is computed once in the shared edge layer from `CodeUnit` ownership and the existing hierarchy relations, and both producers get it from that one computation. The per-language same-owner policies inside usage strategies are not rewritten in this plan; where a strategy's policy disagrees with the shared classification, that disagreement is *reported* by the conformance fixtures and filed, not silently normalized.
  Rationale: `5f553eaf3`'s lesson is that per-language classification drifts; one computation is the fix, but rewriting eleven usage strategies in this slice would swallow the plan.
  Date/Author: 2026-08-05, Fable 5.
- Decision: edge-parity asserts extend the existing `assertion` analysis kind with new record families rather than a new analysis kind, following #1474's decision for resolution asserts verbatim. The subject of a parity assert is a declaration-set capture (not a single token), and the assert names the projection fields it compares; classifications are compared explicitly per field, and a count comparison is not expressible in the form at all.
  Rationale: the acceptance criterion "never inferred from counts" is enforced structurally by not offering counts; the kind's completeness accounting must stay single.
  Date/Author: 2026-08-05, Fable 5.
- Decision: fail-unreliable inputs are enumerated up front: an unsupported edge axis for a language in scope; `FuzzyResult::TooManyCallsites` or the reference-candidate cap (`ReferenceCandidatesOmitted` / `exhausted`); resolver diagnostics on a seed's forward batch; `FuzzyResult::Failure`; and a workspace-generation mismatch between the two projections. Each maps to the existing `PolicyIncompleteReason` vocabulary; none yields a finding or a clean pass.
  Rationale: the rule contract says unknown edges may stay partial but surfaces must preserve compatible uncertainty; an assert over a truncated set is not evidence.
  Date/Author: 2026-08-05, Fable 5.
- Decision: both projections run against one immutable workspace generation, stamped on every edge row, and the parity evaluator refuses to compare rows from two generations. The stamp reuses the analyzer's existing per-generation query-index identity (`workspace.rs` builds lazily-initialized per-generation query indexes) rather than minting a new counter.
  Rationale: cross-generation comparison manufactures phantom mismatches; the identity already exists.
  Date/Author: 2026-08-05, Fable 5.
- Decision (M2): the projection helpers stay in `search/expansions.rs` at `pub(crate)` visibility and the edge layer consumes them, rather than physically moving them as the Plan of Work sketched. `reference_hits_for_target` and `classify_reference_kind` are pure functions of an analyzer and usage values with no search-internal state, so the byte-identical guarantee for `references-of` is trivially preserved by not moving them at all; ownership can migrate to the edge module in Milestone 4 when the query steps consume canonical rows, if that migration pays for itself then.
  Rationale: the smallest refactor that shares the code; a verbatim move now would be churn with no consumer to justify it.
  Date/Author: 2026-08-05, Fable 5.
- Decision (M2): a forward occurrence whose target is `Lexical`, `Unresolved`, or `None` contributes no edge row and no incompleteness reason. That is data about the forward surface, not a derivation gap: the parity comparison finding an inverse edge with no forward counterpart at such a site is precisely the mined regression shape. Ambiguity is preserved as uncertainty instead: a multi-target resolution emits one row per target, each `Unproven`.
  Rationale: the rule contract says surfaces preserve compatible uncertainty; suppressing the rows or calling them incomplete would both hide the disagreement the layer exists to expose.
  Date/Author: 2026-08-05, Fable 5.
- Decision (M3): receiver evidence is not threaded onto edge rows in this plan. The plan sketched carrying receiver evidence from the #1474 trace and `ReceiverTargetRef`, but the only classification this slice needs it for — self-reference — falls out of unit equality between the site's enclosing declaration and the target, and a receiver-evidence field with no consumer would be YAGNI weight that #1477 (receiver/member dispatch) will design properly. If a Milestone 6 fixture turns out to need it, that fixture files the follow-up against #1477.
  Rationale: do not build a field for a sibling issue's domain before that sibling designs it.
  Date/Author: 2026-08-05, Fable 5.
- Decision (M3): owner-relation `Unknown` is the answer whenever the site's enclosing declaration is missing, either owner is missing, or two distinct class owners cannot be checked for inheritance because no type-hierarchy provider exists. `External` is only ever stated when inheritance is ruled out (a non-class owner, or a hierarchy check that ran and failed). Both producers push `AxisUnsupported(OwnerClassification)` for adapters that do not claim the axis, so best-effort classifications are visible but never vouched complete — the #1474 M3 rule ("report everything honestly derivable, let completeness say what it does not cover") applied to classification.
  Rationale: `Unknown` collapsing into `External` is precisely the classification drift the mined commit `5f553eaf3` fixed by hand once already.
  Date/Author: 2026-08-05, Fable 5.
- Decision (M5): the parity comparison lives inside the assert evaluator as a site-identity anti-join over the two derivations, not as a free-standing query-surface equijoin/symmetric-difference operator family. The plan sketched general relational operators, but the only consumer this slice has is the parity assert, whose comparison key is fixed by the contract (site identity, target, and the classification fields); a general keyed-join surface with no second consumer would be YAGNI machinery to maintain through every schema bump. If a query author needs raw set comparison, `union`/`intersect`/`except` over edge rows already exist because edge rows are typed endpoints. A general projection/equijoin surface should be designed when a second consumer names its key.
  Rationale: the acceptance criteria are about the assertion; build the comparison where its key is a contract.
  Date/Author: 2026-08-05, Fable 5.
- Decision (M5): the assert families are token-anchored with the direction derived from the asserted role, not declaration-set-anchored. A reference-class role checks forward-into-inverse at the captured token; `declaration_name` checks inverse-into-forward for the declaration the token names, bounded to the files the inverse listing itself names. This reuses the assertion kind's capture join, role narrowing and soundness accounting unchanged, and both mined directions (a site the listing missed; a listed site the resolver disowns) are expressible by choosing the role.
  Rationale: the #1474 decision that new asserts extend the existing kind, applied to the anchor as well.
  Date/Author: 2026-08-05, Fable 5.
- Decision (M5): `usage_kind` is excluded from the field-for-field comparison and `:surface` is the explicit usage-surface comparison instead, with both sides surface-projected. The forward producer states `reference` unconditionally because usage-kind classification (import binding, re-export, self receiver) is the inverse index's analysis; comparing the raw field would report the producers' vocabulary difference on every self call rather than a real edge disagreement.
  Rationale: compare what both producers actually claim; surface membership is the shared, checkable form of the classification.
  Date/Author: 2026-08-05, Fable 5.

## Outcomes & Retrospective

Milestone 6 and plan closure (2026-08-05): the acceptance criteria all hold in demonstrable form. One assertion compares the forward and inverse edge sets within one generation (`assert-edge-parity`, refused across generations); findings name the unmatched edge with both provenance descriptions and Evidence locations; every claimed language has exact parity positives (Java, Python, Rust, TypeScript each pin field-for-field agreement at a real call site) plus the near-miss families from the issue text (declaration heads yield no forward edge, wrong-package targets are asserted absent, the unindexed-external boundary stays out of parity claims); and proof plus usage-surface classification are compared as explicit fields and surface projections, with counts structurally inexpressible in the assert forms. The retrospective lesson worth carrying to the remaining siblings: the honest-abstention spine did most of the design work. Every difficult call in this plan (usage-kind exclusion, role-scoped forward coverage, surface-projected counterparts, Unknown-never-External, generation refusal) was resolved by asking which producer actually states the value, and each of the six filed follow-ups (#1638-#1640, #1644-#1646) is a place where that question exposed a real engine gap rather than a plan gap -- which is precisely the mined inventory's thesis that parity assertions find bugs.

Milestone 5 (2026-08-05): the asserts landed with three corrections the tests forced, each now part of the contract. ## Context and Orientation

Bifrost is a Rust workspace. The analysis crate (`crates/bifrost-analysis`) hosts per-language analyzers, the structural facts arena, the RQL/CodeQuery engine, and the usage machinery. The policy crate (`crates/bifrost-policy`) hosts RQLP: policy packs whose rules are RQL queries plus analyses (including the `assertion` kind) with findings, completeness accounting, and renderer parity. "RQL" is the s-expression/JSON query language; "RQLP" is the policy layer over it. A "facts arena" is the per-file flattened AST snapshot (`structural/facts.rs`) whose nodes carry stable content-scoped identities (`ast_id`); occurrence rows, lexical environment rows and structural captures all join on those identities.

The forward reference surface: `structural/occurrence_rows.rs` classifies identifier tokens per file and, for reference-class tokens, runs the `get_definition` resolver batch, collapsing each outcome into `OccurrenceTarget` (`Resolved(Vec<CodeUnit>)`, `Lexical(...)`, `Unresolved(status)`). Since #1474, an opt-in trace (`analyzer/usages/get_definition/trace.rs`) records resolution candidates with precedence tiers, typed rejections, and `BoundaryStatus`. Wire shape: `CodeQueryOccurrence` with `ast_id` and `CodeQueryOccurrenceTarget` (`search/results.rs:1137, :1161`).

The inverse reference surface: `analyzer/usages/` hosts `find_usages` (per-language strategies returning `FuzzyResult` with proven and unproven `UsageHit` sets per overload), the whole-workspace inverted edge build for `usage_graph` (`inverted_edges.rs`), and call relations (`call_relations.rs`). `UsageHit` carries `kind: UsageHitKind`, `proof: UsageProof`, optional `reference_kind: ReferenceKind`, and an `enclosing: CodeUnit`; `UsageHitSurface::included_in` decides external-usages vs editor-visible membership. The RQL steps `references-of`, `used-by`, `uses`, `callers` (`query/schema.rs:885-912`) consume this surface; `search/expansions.rs` performs the projection and carries the truncation diagnostics.

The comparison machinery that exists: `SetOperator::{Union, Intersect, Except}` (`query/ir.rs:800`) over compatible typed endpoints; typed value kinds already include `ReferenceSite` and `CallSite` (`ir.rs:47`). What does not exist: any keyed join, anti-join, symmetric difference, field projection, an edge row shared by both directions, owner-relation data, or a parity assert.

The assertion machinery: `crates/bifrost-policy/src/schema.rs` registers assert record families; the evaluator (from #1473, extended by #1474) joins captures to rows by `ast_id`, aggregates per-axis completeness, and yields `Inconclusive` on incomplete inputs. Schema versions live in `query/ir.rs` (`RESOLUTION_SCHEMA_VERSION = 9` is current; this plan bumps to 10 when the edge domains land).

## Validation and Acceptance

Acceptance restates the issue's criteria as observable behavior: (1) one RQLP assertion compares complete forward and inverse proven edge sets in one workspace generation, demonstrated by the parity suite fixture failing on a seeded one-sided edge; (2) its finding names the unmatched edge and both provenance chains, pinned by a renderer-parity test; (3) every claimed language has exact parity positives and the near-miss families listed in Milestone 6; (4) proof and usage-surface classification are compared as explicit fields — the assert form has no count comparison to misuse; (5) truncation, diagnostics, unsupported axes, and stale generations each yield `unreliable`, pinned by dedicated fixtures.

## Idempotence and Recovery
